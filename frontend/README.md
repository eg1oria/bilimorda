# Bilimorda frontend

Next.js-интерфейс регистрации, прохождения теста, просмотра результата и
внутренняя админка.

## Локальный запуск

1. Запустите backend на `127.0.0.1:3001`.
2. Скопируйте `.env.example` в `.env.local`.
3. Укажите тот же `ADMIN_API_KEY`, что и в backend.
4. Создайте секретный URL-токен, например командой `openssl rand -hex 32`, и
   запишите его в `ADMIN_ROUTE_TOKEN`.
5. Укажите origin сайта в `SITE_URL` без пути и завершающего `/`. Для локальной
   разработки используйте `http://localhost:3000`, для production — реальный
   публичный домен с `https`.
6. Выполните `npm install` и `npm run dev`.

Русская версия формы доступна по `/ru`, казахская — по `/kk`; `/` постоянно
перенаправляет на `/ru`. Админка доступна по `/manage/<ADMIN_ROUTE_TOKEN>` и
остаётся русскоязычной. Ссылка на неё нигде в публичном интерфейсе не
публикуется. Она даёт полный доступ к персональным данным, поэтому её нельзя
передавать третьим лицам.

После регистрации активная попытка открывается на `/<lang>/test`, а завершённый
профиль — на `/<lang>/result`. Токен попытки хранится только в `sessionStorage` и
не попадает в URL. Раздел вопросов находится по
`/manage/<ADMIN_ROUTE_TOKEN>/questions`; изменения начинают действовать только
после публикации новой версии.

## Проверка и сборка

- `npm run lint` — ESLint.
- `npm run build` — production-сборка; требует корректный `SITE_URL`.

Для VPS frontend должен иметь сетевой доступ к `BACKEND_INTERNAL_URL`, а сам
NestJS рекомендуется оставлять доступным только на loopback-интерфейсе.
